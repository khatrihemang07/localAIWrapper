# `reasoning_effort` as a per-request field, not a `models.json` entry

Both backend CLIs expose a native per-turn reasoning-effort control: `claude -p --effort <level>` (`low`, `medium`, `high`, `xhigh`, `max`) and `codex exec -c model_reasoning_effort=<value>` (`minimal`, `low`, `medium`, `high`). Neither was reachable from a chat-completions request before this change — codex's value was only settable by hardcoding it into a Model's `args` in `models.json` (e.g. `codex-fast`), and claude's `--effort` wasn't wired in at all.

OpenAI's own chat-completions wire protocol already carries `reasoning_effort` as a per-request body field for reasoning-capable models. Baking it into `models.json` instead would mean a separate Model entry per effort level per backend (`codex-low`, `codex-medium`, `codex-high`, ...), and smuggling a per-request value through the static `args` escape hatch doesn't work — the same limitation ADR-0002 already hit with `--system-prompt`: a chat-completions request needs to override a configured default per Turn, which a verbatim `args` entry can't express.

So `reasoning_effort` is threaded as a typed parameter through `Backend.buildArgs(model, prompt, stream, reasoningEffort)` — the same path `stream` already uses — rather than through `args`. `src/openai.ts` validates that the request value is a member of the union of both backends' vocabularies (`minimal | low | medium | high | xhigh | max`); it does not cross-check the value against the resolved model's backend. Sending `minimal` to a claude-backed model, for instance, passes request validation and then fails inside the `claude` CLI itself. This matches how flag-value legality is already handled elsewhere in this codebase (codex's own args are never validated in code either) — adding a second backend-to-valid-values table in `server.ts` would duplicate what each CLI already enforces.

`models.json`'s existing `codex-fast` entry (`-c model_reasoning_effort=low`, still in its static `args`) is untouched. Since the request-level flag is appended after `model.args` in `codex.ts`, a request that sends its own `reasoning_effort` still overrides it.
